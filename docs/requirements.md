# Noobty 需求共识

> 本文档是 grilling 会话的产出，记录已确认的产品需求与关键决策。术语见根目录 [CONTEXT.md](../CONTEXT.md)，架构权衡见 [ADR-0001](./adr/0001-hub-dual-mode-transfer.md)。

## 一句话定位

**Noobty** 是自托管的局域网传输中枢：以局域网内常驻的 Ubuntu 服务器为中枢，设备之间以聊天室的形式互发文字与文件，替代"用微信传压缩包"（上行慢、有大小限制）的场景；长期演进为局域网综合工具箱。

## 用户与设备

- 用户本人（及可信任的局域网使用者）：多台 Windows PC + 安卓手机。
- 中枢：局域网内常驻的 Ubuntu 服务器（局域网静态 IP，只存在于服务器本地配置，不写入仓库）。
- 任何设备（含客人的 iPhone/Mac/笔记本）通过浏览器即开即用。

## 核心决策一览

| 决策点 | 结论 |
| --- | --- |
| 消息模型 | 聊天式：**私聊**（以设备为联系人）+ **大厅**（广播会话），设备平等，均在 v1 |
| 传输拓扑 | **中枢式**，双模式：「寄存」+「直转」（理由见 ADR-0001） |
| 访问控制 | v1 **无鉴权**，纯局域网信任；暴露公网前必须先加鉴权（硬性约束） |
| 公网访问 | v1 不做；架构上不写死局域网假设 |
| 客户端形态 | 多端通用网页 UI + 主力 PC 的 Tauri 2 托盘壳（复用网页 UI，不做第二套界面） |
| 技术栈 | Rust：axum/tokio 服务端 + Tauri 2 壳；网页前端 TypeScript；serde 共享类型 |
| 部署 | 服务器自建：git 拉取 + 本地编译 + systemd 守护；不用 Docker、不用 GitHub Actions（见下） |
| 品牌/仓库 | 品牌 Noobty；仓库 `noobty`（monorepo：server / web / shell），public 开源 |

## v1 功能清单

核心传输：

- 私聊：选择目标设备发送消息（文本或文件）；对方在线可选直转，离线自动落为寄存。
- 大厅：所有设备可见可取的广播会话。
- 文件上传/下载，分块传输 + 进度显示。
- **断点续传**：大文件（尤其经 WiFi）中断后可续传。
- **多文件/文件夹批量**发送。
- 文本/片段共享（链接、验证码等）。
- 传输历史：按会话呈现聊天记录，文件可重新下载、可删除。
- 在线状态：中枢维护设备列表与在线状态（WebSocket 心跳）。

寄存策略（均可配置）：

- 单件保留 **5 天**，到期清理。
- 寄存区总容量上限 **30GB**；达到上限后**按上传时间从旧到新**清理。
- 文本消息长期保留。

客户端体验：

- 网页 UI：手机扫码/输一次 IP 即可使用；侧栏可出示中枢邀请二维码；PWA 可加桌面图标。
- 托盘壳（Tauri 2）：来件系统通知；默认自动接收，存入 `下载\Noobty`；拖拽发送；网页 UI 内嵌其中。
- 手机网页端：点按接收后开始流式接收（浏览器手势要求）。

## 明确排除 / 后续版本

- v2：鉴权（访问码）+ 公网暴露（frp/Tailscale/域名）。
- v2+：工具箱功能（剪贴板同步、消息通知、设备管理/远程关机等）——托盘壳即为此预留的宿主。

## 非功能需求

- 速度：内网千兆下，寄存模式实际吞吐约为线速一半（上传+下载各一次），直转模式接近线速；均应远快于微信，无单文件大小限制（只受寄存策略约束）。
- 常驻性：中枢服务随服务器开机自启，崩溃自动拉起（systemd Restart 策略）。
- 安全：v1 依赖局域网信任边界；任何形式的公网暴露前必须先落地鉴权。

## 技术栈与结构

- **server**：Rust + axum/tokio；HTTP（上传/下载/分块/续传）+ WebSocket（消息推送、心跳、在线状态）；托管网页静态资源，单进程。
- **web**：TypeScript + 轻量前端框架，构建产物由 server 托管。
- **shell**：Tauri 2（Rust 核心 + 系统 WebView2），内嵌中枢地址（由配置指定）。
- 类型共享：serde 结构体定义一份，前后端复用。

## 部署（无 Docker、无 CI/CD）

- **服务器自建**：中枢服务器直接 `git clone` 本公开仓库，在服务器本地编译运行：
  1. 工具链：git、Rust（rustup）、Node.js ≥ 20。
  2. `cp config.example.toml config.toml`，按需修改（端口、寄存目录、过期天数、容量上限、清理策略均可配）。
  3. 构建 web（`npm ci && npm run build`）与 server（`cargo build --release`）。
  4. 安装 systemd 单元（`deploy/noobty.service`）：开机自启、崩溃自动拉起。
- **升级**：在服务器上执行 `deploy/deploy.sh`（git 拉取 → 重建 → 重启 → 健康检查）。
- 不用 Docker、不依赖 GitHub Actions（公网 runner 无法直连内网中枢，自建脚本更简单可靠）。
- 具体地址等环境信息只存在于服务器本地 `config.toml`，不入仓库。详见 [DEPLOYMENT.md](./DEPLOYMENT.md)。

## 里程碑

1. **M1**：服务端 + 网页核心——寄存模式、私聊、文本/文件、进度、断点续传、历史、在线状态。此刻全设备已可用。
2. **M2（已落地）**：大厅、直转（边传边收+落盘）、多文件/文件夹批量（`file_group`）。
3. **M3（已落地）**：Tauri 托盘壳（通知、自动接收到「下载/Noobty」、HTML5 拖拽发送）。
4. **M4（v2）**：鉴权 + 公网；工具箱功能起步。
